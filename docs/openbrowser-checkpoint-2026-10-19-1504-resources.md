## Problem and root cause
- Before fix, sampler accepted only processes whose command line included '--chatgpt-lite'. Current production application uses '--lite-open-safely'.
- Real file resources-2026-10-19.jsonl on PBOX1 at 14:57:07 CEST showed hostCount=0, webviewCount=7 even though PID21332 of v1.72.6 was alive.
- The existing Windows task 'OpenBrowser Lite Resource Monitor' runs every approximately 2 minutes and invokes local monitor-lite-resources-hidden.vbs, which in turn executes the on-disk PowerShell sampler.

## Changes
- Expanded matching to '--(chatgpt-lite|lite-open-safely)(\s|$)' to support both launch modes.
- Before editing the PBOX1 runtime script, saved the original at:
  %LOCALAPPDATA%\OpenBrowser\ChatGPT-Lite\diagnostics\monitor-lite-resources.before-20261019-1500.ps1.bak
  Backup SHA256 F71F786B7901997DBB54A76EF24DFE0AB2B81E698A6185AEC23118F695EDDBFD.
- Added adjacent-sample CPU rate computation for unchanged PIDs: cpuCorePercent = 100 * (delta cumulative CPU seconds) / elapsed wall seconds; cpuMachinePercent = cpuCorePercent / logical processor count.
- Require 2 <= elapsed seconds <= 900; skip PID changes, negative deltas, and corrupt samples without fabricating rates.
- Added logicalProcessors and cpuSampleIntervalSeconds to resource JSONL records.
- Only metadata/process counters recorded; no prompts, full URLs, cookies or model content.
