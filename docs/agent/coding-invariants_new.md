## Current invariants
### INV-FOLDER-001: Folder policy coverage

Rule: Every folder must be covered by docs/agent/folder-policy_new.md, a local FOLDER.md, or an inherited parent FOLDER.md. New root folders require explicit policy update or architect approval.

Reason: Uncontrolled folder creation pollutes the repository and makes agent work harder to verify.


### INV-ENC-001: Explicit UTF-8 for generated text files

Rule:
PowerShell-generated files, Python-generated files, generated documentation, generated scripts, reports, logs, JSON, markdown, and command output files must use explicit UTF-8.

Reason:
Windows defaults may corrupt Polish characters, quotes, command output, markdown, JSON, or logs.

Applies to:
- PS executor usage
- PY executor usage
- PowerShell scripts
- Python scripts
- BAT/PS helper scripts
- generated markdown files
- generated docs
- log-cleaning scripts
- file-writing automation

Required behavior:
Use explicit UTF-8 when writing files. Do not depend on default encoding.

Source evidence:
- docs/development/journal.md records UTF-8 fix in GeneralCommandExecutor using StandardOutputEncoding and StandardErrorEncoding.
- docs/development/rules.md requires current working rules for agents.

### INV-DOC-001: Documentation impact must be checked after behavior changes

Rule:
If a change affects behavior, commands, modules, executors, paths, logs, output format, help text, status text, prompts, tests, or runtime rules, documentation impact must be checked.

Reason:
The next developer agent must be able to continue from repository knowledge, not from old conversation memory.

### INV-DOC-002: Newest and most important information stays near the top

Rule:
Documentation must place newest, current, and operationally important information near the top.

Reason:
Long-running AI sessions may lose lower-context details. Important rules must be visible early.

### INV-REM-001: Removed features leave no active-file ghosts

Rule:
When a feature is removed, every trace of it must be erased from active files.

Applies to:
- code
- docs
- handoffs
- journals
- test plans
- README files
- comments
- config
- variable names
- file names

Forbidden:
- deprecated comments
- removed-in-version notes in active docs
- commented-out code
- _old suffixes
- was-lines
- stale parser comments
- stale handoff references treated as active truth

Reason:
Stale references pollute agent context and cause agents to hallucinate nonexistent features.

Source evidence:
- docs/development/rules.md contains Feature removal HARD RULE.

### INV-ARCH-001: No unapproved architecture expansion

Rule:
Do not create new layers, services, managers, registries, factories, dispatchers, queues, watchdogs, cross-tab systems, or multi-tab registries without explicit approval or explicit task scope.

Reason:
The project must avoid accidental architecture growth caused by agent speculation.

Source evidence:
- docs/development/rules.md prohibitions.

### INV-TOOL-001: Do not restore rejected old components

Rule:
Do not restore the old BridgeBrowserHelper or old Cloud Code connector.

Reason:
Those directions were removed/rejected and must not re-enter active architecture accidentally.

Source evidence:
- docs/development/rules.md prohibitions.
- docs/development/journal.md records removal of legacy BridgeBrowserHelper and Cloud Code connector.

### INV-BUILD-001: C# changes require build validation

Rule:
After every change to .cs files, run dotnet build.

Specific validations:
- after OpenBridgeProtocol changes, run tests/OpenBridgeProtocolSmoke/OpenBridgeProtocolSmoke.csproj;
- after OpenBridgeHost or executor changes, run tests/OpenBridgeHostSmoke/OpenBridgeHostSmoke.csproj.

Known exception:
- MSB3277 WindowsBase warning can be ignored only if there are 0 errors.

Source evidence:
- docs/development/rules.md Build and Tests.

### INV-REG-001: Module registry is only a registry

Rule:
docs/runtime/modules-index_new.md stores module name, type, status, and docs path. It does not store common documentation rules.

Reason:
Common rules belong in templates and documentation checklists, not in every registry entry.

### INV-HELP-001: Help text should be file-backed

Rule:
Runtime help and executor help should be stored in documentation files and read by code, not hardcoded as long strings.

Reason:
Help content is project knowledge and must be maintainable without hunting through runtime code.

### INV-SEC-001: Local-only runtime boundary

Rule:
Open Browser is designed for local use and must not be exposed to the Internet.

Reason:
Security sources state that the project has no authentication or network security layer for public exposure.

Source evidence:
- SECURITY.md

### INV-SEC-002: Secrets stay in config/local

Rule:
Secrets, API keys, tokens, credentials, and local config belong in config/local and must not be committed or logged.

Reason:
Tool and security sources consistently identify config/local as the git-ignored secrets location.

Source evidence:
- SECURITY.md
- config/local/README.md
- tools/* documentation
### INV-CMD-001: Prefer simple commands over defensive complexity

Rule:
Developer agents should prefer short, direct, single-purpose commands over complex defensive PowerShell scripts.

Examples:
- use mkdir, dir, copy, Get-Content, Set-Content, Get-Item, Select-String for simple work;
- verify immediately after a write or filesystem operation;
- avoid large inline error-handling blocks when a simple command plus verification is safer;
- split work into inspect, write, verify steps instead of one large fragile command.

Reason:
Overcomplicated commands often introduce parsing, quoting, escaping, and PowerShell syntax errors. A command intended to prevent errors can become the source of errors.

Operational rule:
If a simple command can do the job, use the simple command. If the command becomes long, quote-heavy, multi-line, JSON-heavy, markdown-heavy, or OpenBridge-sensitive, use RAW payload instead of manual escaping.

Source evidence:
- docs/runtime/environment.md
- docs/executors/PS/help_new.md
- docs/executors/PS/rules_new.md

### INV-HELP-001: Help commands must map to explicit files

Rule: Every model-facing help command must have a documented source file. Tool help commands display tools/<tool>/README.md and must state the file path in output.

Reason: Models must not search random README files or infer tool usage from stale documentation.

### INV-TRANSPORT-001: Text transport must be explicit

Rule: OpenBridge text transport between model, Host, executor, and result return must not rely on undocumented default encodings or accidental shell behavior.

Reason: payload text and returned output can include Unicode, markdown, JSON, command frames, quotes, and backslashes. These must survive both directions.

### INV-FEEDBACK-001: Recurring model-operational failures must be recorded

Rule: Repeated command failures, misleading help, wrong capability assumptions, legacy-document confusion, and tool behavior mismatches must be recorded according to docs/agent/model-feedback-policy_new.md.

Reason: If a model repeatedly makes the same wrong assumption, the system documentation is probably insufficient.
